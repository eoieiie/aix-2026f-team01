# 팀원 안내

만드는 일은 AI에게 시키고, 우리는 화면을 보면서 확인하고 승인한다. 처음 들어왔으면 이 한 장만 읽으면 된다.
아래 프롬프트는 저장소 파일을 읽을 수 있는 AI(클로드, 안티그래비티 등)에 그대로 넣는다.

## 0. 어디에 무엇이

| 할 때 | 볼 곳 |
| :-- | :-- |
| AI에게 일을 시킬 때 | 아래 프롬프트. AI가 `team/AGENTS.md`를 먼저 읽는다 |
| 무엇을 만드는지 | `docs/spec.md` (제품 명세) |
| 내 담당과 완료 조건 | GitHub 이슈 (번호는 `docs/spec.md` 10절 표) |
| 지금까지 정한 것 | `docs/decisions.md` |
| 팀 규칙, 작업 규칙 | `docs/team-rules.md`, `team/WORKFLOW.md` |
| 지금 화면 | 합쳐진 것: https://babti.expo.app, 작업 중인 것: 각 PR 댓글의 미리보기 주소 |

## 1. 작업 흐름

1. 처음 한 번: 프롬프트 ①. AI가 내 담당과 끝의 기준을 설명하면 맞는지 확인한다.
2. 작업 시작: 프롬프트 ②. AI가 브랜치를 만들고 내 노트북에 웹 미리보기를 띄운다. 브라우저를 열어 두면 AI가 고칠 때마다 화면이 바로 바뀐다. 첫 커밋을 올리면 AI가 draft PR을 열고, 그 뒤로 push할 때마다 PR 댓글의 미리보기 주소가 바뀌어서 팀원도 폰으로 볼 수 있다.
3. 다음 날 이어서: 새 대화에서 프롬프트 ③.
4. 완료 조건을 다 채웠을 때: 프롬프트 ⑤. 화면에서 직접 눌러 보고, 맞으면 AI가 기록을 남기고 PR을 리뷰 상태로 바꾼다. 리뷰어는 다음 순번이고 자동 머지가 걸린다.
5. 리뷰를 맡았을 때: 프롬프트 ⑥. PR 댓글의 미리보기 주소에서 완료 조건을 눌러 보고, PR 본문의 동작 원리를 읽고 승인한다. 이해가 안 되면 반려한다. 미리보기가 안 뜨면 프롬프트 ⑧.
6. 승인되면 자동으로 머지되고, 1분쯤 뒤 https://babti.expo.app 이 바뀐다.
7. 막히거나 충돌이 나면: 프롬프트 ⑦.

흐름 중간에 무엇을 정했거나 버렸으면 "기록해"라고 한다 (프롬프트 ④). 기록은 PR 본문에 들어가고, 매주 활동지를 쓸 때 파일로 모은다 (프롬프트 ⑨).
PR은 작게 나눈다. 화면 하나나 완료 조건 한두 개씩. 리뷰가 화면 몇 번 누르기로 끝나고, 합쳐진 화면도 자주 바뀐다.

리뷰 순번: 황병주(eoieiie) → 이혁준(Aninnom) → 이학준(Ruty041) → 이재곤(GONI1130) → 황병주

## 2. 프롬프트

① 처음 한 번
```
github.com/eoieiie/aix-2026f-team01 저장소로 팀 프로젝트를 개발한다. 내 GitHub 아이디는 ____ 이다.
1. 저장소가 없으면 clone하고, 있으면 main으로 바꿔 최신으로 받아라.
2. team/AGENTS.md를 끝까지 읽고 이 대화 내내 그 규칙을 따라라.
3. team/README.md, team/WORKFLOW.md, docs/spec.md 전체, docs/decisions.md 마지막 10줄을 읽어라.
4. GitHub 이슈에서 내 담당을 찾아, 무엇을 만들고 어디까지 하면 끝인지, 누구 일이 끝나야 시작할 수 있는지 쉬운 말로 설명해라.
5. 커밋이 내 GitHub 계정으로 찍히는지 git config로 확인해라.
6. npm install을 하고, .env가 없으면 .env.example을 복사해 만들어라. 넣을 값(Supabase 주소와 공개 키)은 나에게 물어봐라.
아직 코드는 쓰지 마라. 내가 설명을 확인한 다음에 시작한다.
```

② 작업 시작
```
이슈 #__ 을 시작한다. team/AGENTS.md 규칙대로 해라.
main을 최신으로 받고 브랜치를 만들고, 내 노트북에 웹 미리보기(npx expo start --web)를 띄워서 주소를 알려줘.
첫 커밋을 올리면 draft PR을 열고, 그 뒤로는 완료 조건 하나를 끝낼 때마다 커밋하고 push해줘.
완료 조건을 하나 끝낼 때마다 무엇을 했는지, 화면에서 어디를 눌러 보면 되는지 알려줘.
완료 조건이 모호하거나 명세와 다르게 해야 할 것 같으면 코드를 쓰기 전에 물어봐. 명세는 고치지 마.
```

③ 다음 날 이어서 (새 대화)
```
team/AGENTS.md를 읽고 따라라. 내 GitHub 아이디는 ____, 이슈는 #__ 이다.
지금 브랜치, 최근 커밋, 열린 PR, PROMPTS.md 표의 내 마지막 줄을 보고 어디까지 했는지 정리하고, 웹 미리보기를 다시 띄워줘.
이슈에서 아직 안 끝난 완료 조건을 알려주고, 다음에 할 하나를 제안해줘. 내가 고르면 시작한다.
```

④ 기록해
```
방금 흐름 기록해. team/AGENTS.md 8절대로 지금 PR 본문의 기록 칸에 PROMPTS 한 줄을 적고, 팀 결정이면 decisions 한 줄도 적어. PR이 없으면 이슈 댓글에. 적기 전에 그 줄을 먼저 보여줘.
```

⑤ 완료 조건을 다 채웠을 때
```
이슈의 완료 조건을 하나씩 다시 확인하고, 화면에서 내가 직접 눌러 볼 순서를 적어줘.
내가 확인하면 PR 본문을 .github/pull_request_template.md 양식대로 채워줘(동작 원리, 눌러 볼 순서, 기록 포함).
그다음 draft를 풀고, 리뷰어를 team/README.md 리뷰 순번의 다음 사람으로 지정하고, 자동 머지를 걸어줘.
```

⑥ 리뷰를 맡았을 때
```
PR #__ 리뷰해줘. team/AGENTS.md를 읽고 따라라.
이 PR이 닫는 이슈의 완료 조건을 하나씩 실제로 확인하고, 확인한 것과 못 한 것을 나눠서 알려줘.
PR 댓글의 웹 미리보기 주소에서 내가 직접 눌러 볼 순서를 적어주고, 동작 원리를 내가 이해할 수 있게 세 줄로, 작성자에게 물어볼 질문 두 개를 정리해줘. 승인 여부는 내가 정한다.
```

⑦ 막히거나 충돌이 났을 때
```
지금 막혔다. 무엇을 하려다 어디서 막혔는지 내 화면의 오류 원문은 이렇다: ____
원인을 추측으로 고치지 말고, 확인한 것과 추측을 나눠서 말해줘.
git 충돌이면 team/WORKFLOW.md 5절대로 처리하고, PROMPTS.md와 docs/decisions.md는 양쪽 줄을 모두 살려. main에는 강제 push하지 마.
```

⑧ PR을 내 노트북에서 보기
```
PR #__ 을 내 노트북에서 띄워줘. team/WORKFLOW.md 4절대로 하고, 다 보면 원래 브랜치로 돌아가.
```

⑨ 이번 주 기록 모으기 (활동지 쓰는 사람)
```
이번 주 기록 모아줘. team/AGENTS.md 8절대로 이번 주에 머지된 PR 본문과 이슈 댓글의 기록 칸을 PROMPTS.md, docs/decisions.md 맨 아래로 옮기고, 이번 주 활동지 PR에 같이 넣어줘. 옮기기 전에 줄 목록을 먼저 보여줘.
```

## 3. 꼭 지키는 것

- 승인은 사람이, 화면을 눌러 보고 동작 원리를 이해한 뒤에 한다. 설명할 수 없는 PR은 승인하지 않는다.
- 명세(`docs/spec.md`)는 회의에서 정한다. 바꾸고 싶으면 이슈나 회의에 올린다.
- 개인정보, 키, `.env`는 저장소에 올리지 않는다.
- 커밋은 내 계정으로 찍힌다. AI 공동저자 줄은 넣지 않는다.
