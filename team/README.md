# 팀원 안내

처음 저장소에 들어왔을 때 이 한 장만 읽으면 된다. 아래 프롬프트는 클로드, 안티그래비티 등 저장소 파일을 읽을 수 있는 AI면 그대로 쓴다.

## 0. 어디에 무엇이

| 할 때 | 볼 곳 |
| :-- | :-- |
| AI에게 일을 시킬 때 | `team/AGENTS.md`를 새 대화 맨 앞에 읽게 한다 (아래 프롬프트에 들어 있다) |
| 무엇을 만드는지 볼 때 | `docs/spec.md` (제품 명세) |
| 내 담당과 완료 조건 | `docs/spec.md` 10절 (회의 뒤엔 이슈) |
| 지금까지 정한 것 | `docs/decisions.md` (중요도 상·중만) |
| AI와 한 흐름이 끝났을 때 | `PROMPTS.md` 표에 한 줄 (`team/AGENTS.md` 8절) |
| 작업 순서, 브랜치, 커밋 | `team/WORKFLOW.md` |
| PR을 열 때 | 자동으로 뜨는 템플릿의 체크박스를 채운다 |

## 1. 작업 흐름

1. 처음 한 번: 아래 프롬프트 ①을 넣는다. AI가 내 담당과 끝의 기준을 설명하면, 맞는지 확인한다.
2. 작업 시작: 프롬프트 ②. AI가 `main`을 최신으로 받고 브랜치를 만든다. 완료 조건을 하나씩 끝낼 때마다 무엇을 했고 어떻게 확인했는지 보여준다.
3. 다음 날 이어서: 새 대화를 열고 프롬프트 ③. 어제 어디까지 했는지 AI가 브랜치와 기록을 보고 다시 잡는다.
4. 한 흐름이 끝났을 때 (무엇을 정했거나, 버렸거나, 배웠을 때): 프롬프트 ④ "기록해". `PROMPTS.md`에 한 줄, 팀 결정이면 `docs/decisions.md`에도 한 줄 들어간다.
5. 완료 조건을 다 채웠을 때: 프롬프트 ⑤. AI가 웹 미리보기에서 확인할 목록을 주고, 기록을 남기고, PR을 연다. 리뷰어는 다음 순번이다. 몇 분 뒤 PR 댓글에 웹 미리보기 주소(`https://babti--pr-<PR번호>.expo.app`)가 달린다.
6. 리뷰를 맡았을 때: 프롬프트 ⑥. PR 댓글의 웹 미리보기 주소에서 직접 눌러 본다. AI가 확인해 주지만 승인은 내가 정한다. 동작 원리가 이해되지 않으면 반려한다.
7. 승인되면 자동으로 머지된다 (PR을 열 때 AI가 자동 머지를 걸어 둔다). 머지된 뒤에는 모두 `main`을 다시 받는다 (AI에게 "main 최신으로 받아줘").
8. 막히거나 충돌이 나면: 프롬프트 ⑦.

리뷰 순번: 황병주(eoieiie) → 이혁준(Aninnom) → 이학준(Ruty041) → 이재곤(GONI1130) → 황병주

## 3. 꼭 지키는 것

- `main`에 직접 push하지 않는다. 모든 변경은 PR로 올리고 다음 순번이 리뷰한다.
- 이해하지 못한 코드는 올리지 않는다. 리뷰어는 동작 원리를 물을 수 있다.
- 명세(`docs/spec.md`)는 회의에서 정한다. 바꾸고 싶으면 이슈나 회의에 올린다.
- 개인정보, 키, `.env`는 저장소에 올리지 않는다.
- 커밋은 내 계정으로 찍힌다. AI 공동저자 줄은 넣지 않는다.
