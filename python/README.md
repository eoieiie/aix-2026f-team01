## 실행

저장소에서 `python/` 폴더만 복사해도 된다. Python 3.9 이상과 표준 라이브러리만 쓰며, 인터넷·패키지 설치·계정·키가 필요 없다.

## 1. 학교 앞 가게 전처리

1. 공공데이터에서 `영업/정상`만 남기고 좌표가 없는 곳은 뺀다. Bessel 1841 중부원점 TM(EPSG:5174)을 역투영하고, 7변수 변환으로 WGS84 위경도로 바꾼다. 정문 `(37.2998, 126.8369)`에서 하버사인 직선거리 1,200m 이내만 남긴다.
2. 업태 `기타`, `정종/대포집/소주방`과 이름에 `닭`이 없는 `호프/통닭`을 뺀다. 같은 이름이나 지점 표기를 비교해 오픈스트리트맵과 겹치면 오픈스트리트맵을 남긴다. 업태로 종류를 나누고 가게 이름과 낱말로 대표 메뉴를 **추정**한다. 실제 판매 메뉴나 도보 경로를 확인한 값은 아니다.
3. 카페는 일반음식점에서 업태와 이름으로, 휴게음식점·제과점에서는 방문 후보의 관리번호로, 오픈스트리트맵에서는 카페·아이스크림·빵집 추출본으로 고른다. 코지홀리데이는 공공데이터 좌표가 없어 [PR #96의 자료 설명](https://github.com/eoieiie/aix-2026f-team01/pull/96/files)에 적힌 오픈스트리트맵 건물 좌표를 사용한다. 방문 후보 표시는 현재 제휴 상태를 뜻하지 않는다.
4. `out/restaurants.csv`, `out/cafes.csv`를 생성하고, 2026-11-25 서버 추출본과 `source_id`로 대조한다. 이 스크립트는 앱이나 서버 데이터를 수정하지 않는다.

| 단계 | 이 소스 실행 결과 | PR #96의 `docs/dataset.md`와 서버 추출본 |
|---|---:|---|
| 사동 일반음식점 입력 → 영업 중 → 좌표 있음 → 정문 1.2km 이내 → 식사 가게 → 중복 제외 | 649 → 649 → 647 → 270 → 195 → 180 | PR #96의 11/16 영업 중 입력 651곳, 중복 제외 182곳 |
| 오픈스트리트맵 식당 | 27 → 26 | PR #96: 26곳 |
| 식당 합계 | **206** | PR #96 및 11/25 서버 추출본: **208** |
| 카페: 일반음식점 / 휴게음식점·제과점 / 오픈스트리트맵 | 17 / 9 / 8 | PR #96: 17 / 9 / 8 |
| 카페 합계 | **34** | PR #96 및 11/25 서버 추출본: **34** |
| 전체 | **240** | 11/25 서버 추출본: **242** |

휴게음식점·제과점은 상록구 입력 3,602곳 중 영업 중 917곳, 정문 1.2km 안 121곳(커피숍·다방 51곳)이다. 이 경로에서 방문 후보 9곳만 골랐다. 두 원본에서 이름으로 짝지은 식당 15곳 가운데 12곳에서 좌표 차이가 10m 이내였고 중앙값은 3.1m였다. 이는 이름 매칭을 전제로 한 교차 대조이며 현장 측량 결과가 아니다.

서버와 이름·종류·대표 메뉴가 같고 위치 차이가 0.5m 미만인 가게는 239곳이다. **차이 3곳** 중 박혜자낙지마당과 투탑치킨Premium(사동점)은 11/25의 영업 중 일반음식점 추출본에 없다. 빠진 이유는 확인하지 못했고 폐업으로 판단하지 않는다. 포지타노는 개수 차이가 아니라 메뉴 값 차이다. 서버의 0017·0018 마이그레이션에는 `쌀국수`가 있지만 현재 규칙으로는 근거를 찾지 못해 비워 둔다.

## 2. AI 재료 태그 평가

**사람이 확인한 정답표가 없어서 현재 성능 숫자는 없다.** `data/answer_key.csv`에는 열 이름만 있다. 팀원이 비교 대상 메뉴의 대표 조리법이나 가게의 확인 자료를 검토해 `name,tags,source`를 채운다. `tags`에는 확인한 태그를 공백으로 구분해 쓰고, 해당 태그가 하나도 없다고 확인했을 때만 `-`를 쓴다. `source`에는 자료와 확인한 범위를 적는다. 확인하지 못한 메뉴는 넣지 않는다. 태그는 `spicy seafood pork beef chicken wheat dairy nuts egg`만 받는다. 실제 원재료 보증이나 알레르기 안전 판단에는 쓸 수 없다.

- **낱말 표**: 기본 음식 이름과 `food_keywords`가 입력 이름에 들어 있으면 태그를 더한다. 서버 `guess_food_tags`와 같은 부분 일치 방식이다.
- **AI**: 11/25 서버 `foods` 가운데 AI 처리가 끝난 직접 입력 메뉴에서 `name`, `ai_tags`만 보관한다. 모델을 다시 호출하지 않으며, 캐시나 서버의 최종 합산 `tags`를 AI 단독 결과로 쓰지 않는다.
- **합침**: 낱말 표와 AI의 합집합이다. 기존 태그를 빼지 않는다. 세 방법에서 동일한 메뉴를 평가하고, AI 결과가 없는 정답 메뉴가 있으면 비교를 중단한다.
- 정답표가 생기면 메뉴별 태그 적중·과잉·누락을 합산해 정밀도·재현율·F1을 계산한다. 분모가 0이면 `정의되지 않음`으로 표시한다.

## 앱과의 관계

```text
공공 인허가·오픈스트리트맵 → 01 전처리 → 가게 CSV ── 대조 ── 서버 가게 추출본
                                                             ↑ 실제 앱은 서버를 조회
낱말 표 + 서버 AI 태그 추출본 → 02 오프라인 비교 ← 사람이 확인한 정답표
```

가게 CSV와 평가 코드는 수업 제출용이다. 앱은 이 폴더를 호출하지 않으며, 여기서 만든 결과를 서버에 자동 반영하지 않는다.
