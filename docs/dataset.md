2026-11-21 처음 씀, 11-23, 11-26, 11-28 고침 (Aninnom). 학교 앞 식당(명세 4-21)과 먹고 나서 카페(4-23)에 쓰는 가게 데이터를 어디서 받아 어떻게 거르고 바꿨는지 적는다. 숫자는 `supabase/migrations`의 0015~0022 SQL에서 셌고, 6절의 종류와 대표 메뉴는 0040, 0041, 0051을 넣은 뒤 실제 서버에서 다시 셌다(11-26). 폐업한 두 곳을 숨긴 0054는 1절과 8절에 반영했다(11-28). 발표의 "데이터셋 근거와 전처리" 장의 재료다.

## 3. 거르기 (651곳 → 식당 182곳, 카페 17곳)

순서대로 한다.

1. 범위: 정문에서 직선 1.2km 안. 하버사인 거리로 잰다
2. 식당으로 쓰는 업태만 남긴다. 아래 업태는 뺀다
   - "기타"(카페 등). 이 중 카페는 4절에서 따로 고른다
   - "정종/대포집/소주방"(술집)
   - "호프/통닭" 중 이름에 "닭"이 없는 곳
3. 오픈스트리트맵에 이미 있는 가게는 뺀다(같은 가게가 두 번 나오지 않게)

0017에서 처음 골랐을 때(기준점이 틀렸던 때)는 1.2km 안 206곳에서 카페 등 "기타" 46곳, 닭 없는 호프 18곳, 오픈스트리트맵과 겹친 14곳을 빼 128곳이었다(PR #79).

### 3-1. 기준점을 정문으로 고침 (0018)

0017은 기준점을 37.2967, 126.8355로 잡았다. 이 점은 정문이 아니었다(정문에서 남서쪽 약 370m, 확인하지 않고 쓴 값). PR #78 리뷰에서 두 좌표가 다른 것을 찾았고, Aninnom이 오픈스트리트맵으로 정문을 확인했다. "한대정문사거리" 신호등과 "한양대정문" 정류장 옆이고, 이 좌표를 `area_gate('erica')`에 둔다.

같은 원본, 같은 거르기로 정문 기준 1.2km 안을 다시 골라 128곳이 182곳이 되었다(PR #84). 0017과 0018의 `source_id`를 비교하면 58곳이 더해지고 4곳이 빠졌다(PR #84 본문에는 "5곳 지움"으로 적혀 있지만 SQL로 세면 4곳이다). 범위 밖이 된 곳이라도 쿠폰 기록이 걸려 있으면 지우지 않는다.

이 글을 쓰며 SQL의 좌표로 다시 재 보니, 공공데이터 식당 182곳과 오픈스트리트맵 식당 26곳은 모두 정문에서 1,200m 안이다(가장 먼 곳 1,199m, 1,180m). 카페 34곳도 모두 1,100m 안이다.

- 0021: 제휴 카페 9곳(2-3)과 오픈스트리트맵 8곳(2-2)을 더한다. 9곳의 좌표는 0022에서 공공데이터로 바꿨다
- 공공데이터의 등록 이름을 가게가 실제로 쓰는 이름으로 바꾼 곳이 8곳 있다(시저 → 시저커피, 코이노니아 → 코이노커피 등)
- 제휴: 사장님 동의(eoieiie 확인, 11/19)에 따라 방문 후보 18곳을 켰다(레이지그라운드는 폐업으로 0054에서 껐다, 지금 17곳). 쿠폰 문구는 사장님과 정한 뒤 `scripts/partner-on.sql`로 넣는다

## 5. 좌표 변환

- 공공데이터 좌표는 EPSG:5174(Bessel 1841 타원체, 중부원점 TM)다. 지도와 정문 좌표는 WGS84(위도, 경도)라 바꿔야 거리를 잴 수 있다
- 방법: TM 역변환으로 Bessel 위경도를 구하고, towgs84 7변수(이동 3, 회전 3, 축척 1)로 WGS84로 옮긴다
- 확인: 두 원본에 다 있는 가게 밀플랜비, 도스마스의 좌표가 오픈스트리트맵과 2m 안에서 맞았다. 카카오맵 좌표와는 신디도넛 1m, 오쏘커피 3m, 코이노커피 3m였다(0021)
- 남은 것: 변환에 쓴 7변수 값과 변환 코드는 저장소에 없다. 다시 받을 때 같은 결과가 나오게 값을 여기 적어야 한다

## 6. 종류와 대표 메뉴 채우기

화면은 가게의 종류(`cuisine`)와 대표 메뉴(`menus`)로 "이 메뉴 파는 곳"을 고른다(명세 4-21). 공공데이터에는 메뉴가 없어서 짐작으로 채웠다.

업태 → 종류

| 업태 | 종류 |
|---|---|
| 한식, 분식, 식육, 탕류, 냉면집, 횟집 | korean |
| 중국식 | chinese |
| 일식 | japanese |
| 경양식, 패밀리레스트랑, 패스트푸드, 치킨 | western |
| 외국음식전문점 | asian |

공공데이터 식당 182곳의 종류: 한식 123, 양식 21, 아시안 21, 중식 15, 일식 2.

업태만으로 나눈 처음 값(0017, 0018)은 한식 126, 양식 22, 중식 12, 일식 1이었다. 이름으로 종류가 분명한데 업태와 다르게 들어간 7곳을 0041(PR #119)에서 고쳤다. 감자탕집 1곳 양식 → 한식, 짬뽕집과 마라탕집 4곳 → 중식(한식 3, 양식 1), 파스타집 1곳 중식 → 양식, 라멘집 1곳 한식 → 일식. 김기룽쟝족발덮밥(대만식, 중식)과 봉구스밥버거(한식)는 그대로 두었다.

대표 메뉴는 두 칸으로 나눠 둔다(0051, PR #131).
- `menus`: 가게 이름에 근거가 있는 메뉴. 이름에 음식 이름이 그대로 있거나(예: "예산닭갈비.감자탕" → 닭갈비, 감자탕) 별칭 낱말이 있다(스시 → 초밥, 부찌 → 부대찌개 등). 가게 상세의 대표 메뉴, 가게 그림, 결과 화면의 "메뉴 맞음"은 이 칸만 쓴다
- `menus_guess`: 업태로 흔한 메뉴의 짐작(중국식 → 짜장면, 짬뽕, 탕수육 / 분식 → 떡볶이, 김밥, 라면 등). 가게 탭 찾기와 순서에만 쓰고 화면에 메뉴로 보이지 않는다. 짐작한 음식의 종류가 가게 종류와 다르면 버린다

처음에는 두 가지를 한 칸(`menus`)에 넣어서 훠궈집(중국식)에 짜장면이 대표 메뉴로 보이는 식의 문제가 있었다. 그때 기준으로는 182곳 중 67곳에 대표 메뉴가 있었다.

지금 182곳 중 `menus`가 있는 곳은 48곳, `menus_guess`만 있는 곳은 23곳, 둘 다 없는 곳은 111곳이다. 둘 다 없는 곳은 종류로만 맞는다. 제휴 식당이 생기면 메뉴를 직접 넣는다.

## 8. 확인하는 법

- pgTAP `supabase/tests/0018_restaurants_localdata.test.sql`: 공공데이터 식당이 100곳 넘음, 모두 종류가 있음, 짜장면이 대표 메뉴인 중국집 5곳 이상, 정문에서 1,250m(1.2km에 여유 50m)를 넘는 곳 0곳
- pgTAP `0020_cafes.test.sql`, `0021_partner_cafes.test.sql`: 카페가 식당 칸에 섞이지 않음, 제휴 카페가 먼저, 방문 후보 9곳은 제휴, `partner/` 출처 0곳(0022), 식당 제휴는 켜지 않음
- 실제 서버: Supabase 대시보드 SQL 편집기에서
  ```sql
  select split_part(source_id, '/', 1) as src, coalesce(cuisine = 'cafe', false) as cafe, count(*)
  from public.restaurants where area = 'erica' group by 1, 2 order by 1, 2;
  ```
  기대값(0054 뒤): localdata 식당 182, localdata 카페 25(일반음식점 16 + 휴게음식점, 제과점 9), node 식당 25, node 카페 8. 합쳐 식당 207, 카페 33이다. `area = 'closed'`는 2곳(카바레식당, 레이지그라운드)이다. partner는 0이다. 0017 때 들어갔다가 범위 밖이 된 식당에 쿠폰 기록이 있으면 localdata 식당이 그만큼 더 많다
- 6절의 종류: pgTAP `0041_shop_kinds.test.sql`이 이름에 한식 낱말이 있는데 한식이 아닌 곳, 중식 낱말이 있는데 중식이 아닌 곳, 파스타집인데 양식이 아닌 곳이 0곳인지 본다. 실제 서버에서는
  ```sql
  select cuisine, count(*) from public.restaurants
  where area = 'erica' and source_id like 'localdata/%' and cuisine is distinct from 'cafe'
  group by 1 order by 2 desc;
  ```
  기대값(11-26): korean 123, asian 21, western 21, chinese 15, japanese 2

## 9. 다른 학교로 넓힐 때

같은 순서를 그대로 쓴다.

1. 그 학교 정문 좌표를 오픈스트리트맵에서 확인해 `area_gate`에 한 줄 더한다
2. 공공데이터 일반음식점(전국)을 그 동네 법정동으로 받는다
3. 3절의 거르기, 5절의 좌표 변환, 6절의 종류와 메뉴 짐작을 한다
4. 오픈스트리트맵 식당을 받아 겹치는 곳을 뺀다
5. 모임의 `area`를 그 학교로 둔다(0015)
