# 밥비티아이 제품 명세 v1

이 문서는 팀이 같은 것을 만들기 위한 기준이다. 각자 AI 세션을 열 때 이 문서 전체를 컨텍스트로 준다.
명세와 코드가 다르면 이 문서를 먼저 고치고, 그다음 코드를 고친다.
명세는 팀 회의에서 정한다. 회의에서 바뀐 내용은 `docs/decisions.md`에 회의 날짜와 함께 남긴다.

---

## 0. 한 줄

여럿이 밥 메뉴를 정할 때, 못 먹는 사람은 말하지 않아도 빠지고, 결정은 투표와 룰렛이 대신 지고, 먹은 기록이 쌓여 개인과 모임의 음식 프로필이 되는 앱.

- 약: 할랄·알러지·비건처럼 못 먹는 것이 있는 사람이 매번 밝히지 않아도 된다. 메뉴를 정해야 하는 사람의 부담이 줄어든다
- 비타민: 내 네 글자 음식 타입, 같이 먹은 기록을 자랑할 수 있다

---

## 1. 단계와 완료 기준

### 1단계 (MVP-1): 메인 기능 완벽 동작, 화면 3개 이상
메인 기능 = 모임을 만들고 → 링크로 친구가 들어오고 → 후보를 올리면 못 먹는 음식이 자동으로 빠지고 → 익명 투표 → 룰렛 → 결과가 기록되는 한 판.

완료 기준 (전부 만족해야 완료):
- [ ] 화면 4개가 동작한다: 홈, 초대, 모임, 세션
- [ ] 서로 다른 기기(또는 브라우저) 3대로 한 판을 결과까지 끝낼 수 있다
- [ ] 한 사람이 화면에서 바꾼 것(참여, 후보, 투표 진행, 결과)이 나머지 기기에 새로고침 없이 3초 안에 반영된다
- [ ] 못 먹는 것이 등록된 사람이 참여하면, 그 사람이 못 먹는 후보는 자동으로 빠지고 누가 원인인지는 화면에 나오지 않는다
- [ ] 다른 사람의 표를 API로 직접 조회해도 0행이 나온다 (화면이 아니라 서버가 막는다)
- [ ] 룰렛 결과는 서버가 정하고, 모든 기기에 같은 결과가 나온다
- [ ] 결과가 나오면 식사 기록이 자동으로 생기고 모임 화면의 최근 식사에 보인다
- [ ] 초대 링크를 받은 사람은 앱 설치와 가입 없이 웹에서 이름만 적고 투표까지 간다
- [ ] 아래 4절의 "실패할 때"가 1단계 기능 전부에서 명세대로 동작한다
- [ ] 6절의 규칙 테스트가 통과한다

### 2단계: 프로필과 공유
- [ ] 온보딩(이름, 8문항, 네 글자 결과, 아이디)
- [ ] 내 프로필 화면(네 글자, 레벨, 통계, 도감, 같이 먹은 사람)
- [ ] 모임 프로필 카드(못 먹는 것 인원수, 성향)
- [ ] 결과 카드와 이미지 공유
- [ ] 사다리타기 (룰렛 대신 고를 수 있는 연출. 결과는 서버가 정한다는 규칙은 같다)

### 3단계: 출시 준비
- [ ] 설정(아이디 변경, 개인정보처리방침, 이용약관, 계정 삭제, 버전)
- [ ] 한국어/영어
- [ ] 웹 배포, TestFlight 빌드, App Store 제출

### 이번 학기 하지 않는 것
배달앱 연동, 주변 음식점 성분 조사, 지도, 결제·정산, AI 메뉴 추천, 음식 사진.
이유: 외부 API·제휴 없이 성립하지 않거나(발표장 시연 불가), 앱이 고르면 "투표와 룰렛이 정했다"는 가치가 사라진다.

## 2. 기술 스택과 고른 이유

| 무엇 | 쓰는 것 | 이유 |
|---|---|---|
| 앱 | Expo SDK 57 (React Native), TypeScript | 코드 하나로 iOS 앱과 웹을 같이 만든다. 링크를 받은 사람은 웹으로 바로 들어와야 한다 |
| 화면 이동 | expo-router | 파일 이름이 주소가 된다. 초대 링크 `/g/초대코드`를 바로 처리할 수 있다 |
| 화면 꾸미기 | NativeWind (Tailwind) | 디자인 담당이 익히기 쉽다 |
| 서버·DB | Supabase (Postgres) | 서버를 직접 운영하지 않는다. 무료 요금제로 학기 내내 쓸 수 있다 |
| 실시간 | Supabase Realtime | 같은 자리에서 동시에 쓰는 앱이라 즉시 반영이 필요하다 |
| 로그인 | Supabase 익명 로그인 | 링크 받은 사람이 가입부터 하면 이탈한다 |
| 데이터 불러오기 | TanStack Query | 서버 데이터를 저장해 두고 필요할 때 다시 불러온다 |
| 원판 그리기 | react-native-svg | 표 수에 따라 조각 크기가 달라지는 원판 |
| 이미지 공유 (2단계) | react-native-view-shot, expo-sharing | 카드 영역을 이미지로 찍어 공유 |
| 진동 | expo-haptics | 룰렛이 조각을 지날 때와 멈출 때 |
| 링크 복사 | expo-clipboard | 초대 링크 복사 |
| 다국어 (3단계) | i18n-js, expo-localization | 외국인 사용자 |
| 배포 (3단계) | EAS Build·Submit·Update·Hosting | iOS 빌드, TestFlight, 웹 배포, 심사 없는 수정본 반영 |
| 테스트·검사 | Jest, ESLint, tsc | 규칙을 테스트로 고정한다 |
| 자동화 | GitHub Actions | PR마다 검사, Supabase 무료 요금제가 멈추지 않게 매일 한 번 요청 |

사용하지 않는 것: Supabase 스토리지, Edge Function.

## 3. 구조 원칙

1. **규칙은 서버에만 있다.** 거부권 판정, 투표 상한, 룰렛 추첨, 식사 기록은 Postgres 함수(RPC)가 한다. 앱은 결과를 그리기만 한다. 이유: 앱이 정하면 방장이 결과를 조작할 수 있고, 투표 익명은 화면이 아니라 서버 권한으로만 지켜진다.
2. **화면은 DB를 직접 부르지 않는다.** Supabase 호출은 데이터 접근 폴더(`src/api/` 또는 `src/hooks/`) 한곳에만 둔다. 화면 파일에서 `supabase`를 import하지 않는다. 이유: 디자인을 고치는 사람이 데이터 코드를 건드리지 않게 하고, 저장 방식이 바뀌어도 고칠 곳을 한곳으로 모은다.
3. **사람과 모임 소속을 나눈다.** 사람(프로필)은 계정당 하나다. 못 먹는 것과 네 글자는 사람에 붙는다. 모임에는 소속만 있다. 한 사람이 여러 모임에 있어도 못 먹는 것을 다시 적지 않는다.
4. **상수는 한곳에.** 1인당 표 수, 글자 수 제한, 회전 시간처럼 규칙에 쓰는 숫자는 상수 파일 하나에 모은다. 서버에도 같은 값이 있으면 둘이 같은지 테스트한다.
5. **색은 토큰으로.** 화면 파일에 색 코드를 직접 쓰지 않는다. Tailwind 설정의 색 이름만 쓴다.

## 4. 기능 명세

### 4-1. 익명 로그인 (1단계)
- 한 줄 설명: 앱이나 웹을 열면 가입 없이 바로 쓴다
- 흐름: 처음 연다 → 저장된 로그인이 없으면 익명 계정을 만든다 → 첫 화면
- 실패할 때: 익명 로그인 실패 시 전체 화면에 "연결할 수 없어요"와 다시 시도 버튼. 확인 중에는 로딩 표시
- 관련 테이블: auth.users
- 참고: 기기를 바꾸면 계정이 이어지지 않는다. 이번 학기에는 받아들인다

### 4-2. 모임 만들기 (1단계)
- 한 줄 설명: 모임 이름과 내 이름을 적으면 모임과 초대 코드가 생긴다
- 흐름: 홈에서 "모임 만들기" → 모임 이름, 내 이름 입력(프로필에 이름이 있으면 내 이름은 묻지 않는다) → 서버가 모임, 초대 코드, 첫 소속(나)을 만든다 → 모임 화면으로 이동
- 실패할 때: 이름이 비면 버튼이 꺼진다. 서버 오류는 한국어 문구로 모달 안에 표시하고 모달을 닫지 않는다
- 숫자: 모임 이름 1~40자, 내 이름 1~20자, 초대 코드 6자(영어 대문자와 숫자, 헷갈리는 0 O 1 I 제외, 중복 불가)
- 관련 테이블: groups, memberships, profiles

### 4-3. 내 모임 목록 (1단계)
- 한 줄 설명: 내가 속한 모임을 최근에 들어간 순으로 본다
- 흐름: 홈 → 모임 이름과 초대 코드 카드 목록 → 누르면 모임 화면
- 실패할 때: 오류 문구와 다시 시도 버튼. 모임이 없으면 "아직 모임이 없어요" 문구와 만들기 버튼
- 관련 테이블: memberships, groups

### 4-4. 초대 링크 복사 (1단계)
- 한 줄 설명: 모임의 초대 링크를 복사해 단톡방에 붙인다
- 흐름: 모임 화면의 초대 카드를 누른다 → `{웹 주소}/g/{초대코드}`를 복사 → "복사했어요"가 2.5초 동안 보인다
- 실패할 때: 복사가 실패하면 링크 텍스트를 화면에 보여줘서 직접 복사하게 한다
- 규칙: 초대 링크는 앱에서 복사해도 항상 웹 주소다. 앱이 없는 사람이 누르기 때문이다

### 4-5. 초대 링크로 참여 (1단계)
- 한 줄 설명: 링크를 받은 사람이 설치·가입 없이 이름만 적고 들어온다
- 흐름: 링크를 연다 → 모임 이름 표시 → 이름 입력(프로필에 이름이 있으면 "OO(으)로 들어갈게요" 버튼만) → 진행 중인 세션이 있으면 세션으로, 없으면 모임 화면으로
- 이미 소속이면: 묻지 않고 바로 넘어간다
- 실패할 때: 없는 코드면 "모임을 찾을 수 없어요". 같은 모임에 같은 이름이 있으면 "이미 있는 이름이에요". 이름이 비면 버튼이 꺼진다. 네트워크 오류는 다시 시도 버튼
- 규칙: 링크로 들어온 사람은 온보딩으로 보내지 않는다. 참여할 때 이름만 담긴 프로필이 생긴다. 네 글자 테스트는 나중에 프로필 탭에서 한다
- 숫자: 이름 1~20자
- 관련 테이블: groups, memberships, profiles, sessions

### 4-6. 모임 화면 (1단계)
- 한 줄 설명: 멤버와 최근 식사를 보고 "오늘 뭐 먹지"를 시작한다
- 흐름: 모임을 연다 → 초대 카드, 멤버 이름 동그라미, 최근 식사 5개 → 아래 버튼. 진행 중인 세션이 있으면 "진행 중인 판으로", 없으면 "오늘 뭐 먹지"
- 실패할 때: 소속이 아니면 "이 모임 멤버가 아니에요"와 홈으로 버튼. 다른 오류는 다시 시도 버튼
- 숫자: 최근 식사 5개
- 관련 테이블: groups, memberships, meals, foods, sessions

### 4-7. 못 먹는 것 등록 (1단계)
- 한 줄 설명: 못 먹는 재료와 음식을 한 번 적으면 모든 모임에 적용된다
- 흐름: 세션 화면 위쪽(1단계) 또는 프로필 탭(2단계)의 "못 먹는 것" → 태그 고르기, 음식 검색해서 추가, 이유 고르기 → 저장 → 진행 중인 세션의 후보가 다시 판정된다
- 실패할 때: 저장 오류는 한국어 문구로 표시하고 화면에 남는다. 아무것도 안 고르고 저장하면 전부 해제된다
- 태그: 재료 8개(맵기, 해산물, 돼지고기, 소고기, 닭고기, 밀가루, 유제품, 견과류), 식단 3개(할랄, 채식, 비건)
- 이유: 알레르기 / 안 먹어요 / 신념. 판정에는 쓰지 않고 2단계 모임 프로필 집계에만 쓴다
- 숫자: 음식 검색 결과 최대 6개
- 관련 테이블: restrictions(사람 단위), foods

### 4-8. 세션 시작과 참여 (1단계)
- 한 줄 설명: 모임에서 한 판을 연다. 화면에 들어온 사람이 참여자가 된다
- 흐름: 모임 화면에서 시작 → 진행 중인 판이 있으면 그것을, 없으면 새로 연다. 연 사람이 방장이다 → 세션 화면에 들어오면 자동으로 참여자로 등록된다
- 규칙: 한 모임에 진행 중인 판은 하나뿐이다. 거부권은 참여자 기준으로만 판정한다
- 실패할 때: 끝난 판에 들어오면 결과 화면을 보여준다. 소속이 아니면 4-6과 같다
- 관련 테이블: sessions, session_participants

### 4-9. 후보 올리기 (1단계)
- 한 줄 설명: 먹고 싶은 음식을 검색해서 후보로 올리고 한 줄 어필을 붙인다
- 흐름: 음식 검색 → 누르면 후보에 추가 → 서버가 참여자 중 못 먹는 사람이 있는지 판정 → 있으면 줄을 긋고 "못 먹는 사람이 있어서 빠졌어요"로 표시. 내가 올린 후보에는 어필 쓰기와 빼기가 있다
- 거부권 판정 규칙 (서버):
  - 재료 태그: 음식의 태그에 그 재료가 있으면 빠진다
  - 식단 태그: 음식에 짝 표시(할랄→halal_ok, 채식→veg_ok, 비건→vegan_ok)가 없으면 빠진다
  - 음식 직접 지정: 그 음식이면 빠진다
  - 참여자가 새로 들어오거나 못 먹는 것을 바꾸면 그 판의 후보 전체를 다시 판정한다
- 익명 규칙: 누가 원인인지는 화면에도, 다른 사람이 읽을 수 있는 데이터에도 남기지 않는다. 후보에는 "빠졌는지" 여부만 저장한다
- 실패할 때: 이미 올라간 음식은 검색 목록에서 빠진다. 후보 단계가 끝났으면 "이미 투표가 시작됐어요"
- 숫자: 어필 최대 60자, 검색 추천 최대 6개, 기본 음식 40개
- 관련 테이블: candidates, foods, restrictions, session_participants

### 4-10. 투표 시작 (1단계, 방장만)
- 흐름: 방장이 "투표 시작" → 모든 기기가 투표 화면으로 바뀐다
- 실패할 때: 빠지지 않은 후보가 0개면 버튼이 꺼지고 "후보를 하나 이상 올려주세요". 방장이 아닌 사람에게는 버튼 대신 "방장이 투표를 열면 시작돼요"
- 관련 테이블: sessions

### 4-11. 익명 투표 (1단계)
- 한 줄 설명: 후보 중 최대 2개를 찍는다. 누가 무엇을 찍었는지 아무도 모른다
- 흐름: 후보를 누른다 → 찍힘/취소가 바뀐다 → "N/M명 투표했어요" 진행 막대가 갱신된다
- 규칙: 내 표만 읽을 수 있다(서버 권한). 투표 중에는 음식별 표 수도 보여주지 않는다. "투표했는지"만 참여자 단위로 공개한다
- 실패할 때: 3개째를 누르면 "최대 2개까지 고를 수 있어요". 빠진 후보는 누를 수 없다
- 숫자: 1인당 최대 2표
- 관련 테이블: votes, session_participants

### 4-12. 룰렛 (1단계, 방장만)
- 한 줄 설명: 방장이 돌리면 서버가 하나를 뽑고, 모든 기기에서 원판이 돌아 같은 결과에 멈춘다
- 추첨 규칙 (서버):
  - 대상: 빠지지 않았고 1표 이상 받은 후보. 아무도 안 찍었으면 빠지지 않은 후보 전체
  - 확률: 표 수에 비례한다(3표는 1표의 3배). 아무도 안 찍었으면 균등
  - 결과가 정해지는 순간 판을 끝내고 식사 기록을 만든다. 참여자 전원이 그 식사의 참여자가 된다
- 화면 규칙: 원판 조각 크기는 표 수에 비례한다(보이는 것과 확률이 같아야 한다). 결과가 나온 뒤에만 음식별 표 수를 서버에서 받아 그린다. 누가 찍었는지는 받지 않는다
- 연출: 3.6초 동안 5바퀴 돌고 감속한다. 조각 경계를 지날 때 가벼운 진동, 멈출 때 성공 진동. 음식 이름이 7글자를 넘으면 자른다. 화면이 백그라운드여도 4초 뒤에는 결과를 보여준다
- 실패할 때: 후보가 없으면 버튼이 꺼진다. 서버 오류는 한국어 문구로 버튼 아래에
- 관련 테이블: sessions, votes, candidates, meals, meal_participants

### 4-13. 식사 기록 (1단계)
- 한 줄 설명: 룰렛 결과가 자동으로 기록되고 모임 화면에 쌓인다
- 규칙: 사용자가 따로 저장하지 않는다. 결과가 정해지면 서버가 만든다
- 관련 테이블: meals, meal_participants

### 4-14. 온보딩 (2단계)
- 흐름: 이름(링크로 이미 이름이 있으면 건너뜀) → A/B 상황 문항 8개 → 네 글자 결과와 축별 한 줄 설명 → 아이디(건너뛰기 가능) → 홈
- 네 축과 글자: 탐험(탐)↔반복(반), 매운맛(매)↔순한맛(순), 한식(한)↔외국음식(외), 주도(주)↔수용(수)
- 점수: 축마다 2문항, A=+1, B=-1, 평균. 0이면 앞글자를 쓴다
- 근거: 탐험↔반복 축은 Food Neophobia Scale(Pliner & Hobden, 1992)
- 문항 원칙: 성향을 묻지 말고 상황을 준다. 두 답이 다 괜찮아 보여야 한다. 추상어 대신 음식 이름을 쓴다
- 문항 8개는 번역 파일에 둔다 (한국어/영어)
- 실패할 때: 이름이 비면 다음 버튼이 꺼진다. 아이디 중복이면 "이미 쓰는 아이디예요"를 보여주고 화면에 남는다. 저장 실패 시 오류 문구와 다시 시도
- 숫자: 이름 1~20자, 아이디 영어 소문자·숫자·밑줄 3~16자(중복 불가)
- 프로필이 없는 사람은 온보딩으로 보낸다. 예외: 초대 링크, 온보딩, 개인정보처리방침, 이용약관 화면

### 4-15. 내 프로필 (2단계)
- 내용: 네 글자(테스트 전이면 "내 네 글자 만들기"), @아이디, 레벨과 다음 레벨까지 남은 끼니, 총 끼니, 먹어본 음식 수, 같이 먹은 사람 수, 먹어본 음식 도감, 같이 먹은 사람과 횟수, 못 먹는 것 바로가기
- 레벨: 삼각수(1, 3, 6, 10, 15…끼)
- 부제: 같은 음식을 3번 이상 먹었으면 "OO 권위자"
- 공유: 상단 카드를 이미지로 공유. 웹은 텍스트
- 규칙: 공유 이미지에 못 먹는 것은 절대 나오지 않는다

### 4-16. 모임 프로필 카드 (2단계)
- 내용: 태그별로 못 먹는 사람 수(많은 순), 음식을 직접 막은 사람 수, 네 축별 기울기(테스트한 사람만 센다, "테스트한 N명 기준")
- 규칙: 누가 무엇을 못 먹는지는 보여주지 않는다. 인원수만 보여준다

### 4-17. 결과 카드 (2단계)
- 내용: 모임 이름, 날짜, 음식, 같이 먹은 사람과 "OO랑 n번째 밥", 모임에서 이 음식 n번째, 나의 n번째
- 공유: 이미지로. 웹은 텍스트
- 규칙: 못 먹는 것은 나오지 않는다

### 4-18. 설정 (3단계)
- 아이디 변경(입력 중에 형식과 중복 검사), 계정 상태(익명), 개인정보처리방침, 이용약관, 계정 삭제, 버전과 업데이트 출처
- 계정 삭제: 확인 창 → 나 혼자인 모임은 통째로 지우고, 다른 사람이 있는 모임에서는 내 소속과 기록만 지운 뒤 계정을 지운다 → 앱을 처음 상태로 다시 연다
- 개인정보처리방침과 이용약관은 로그인·프로필 없이도 열려야 한다 (앱 심사관이 바로 연다)

## 5. 데이터 모델

| 테이블 | 주요 칸 | 용도 |
|---|---|---|
| profiles | user_id(PK), display_name(1~20), handle(유일, 3~16), quiz_answers(jsonb), axes(jsonb), created_at | 사람 하나당 하나 |
| restrictions | user_id, tag 또는 food_id 중 하나, kind(allergy/dislike/belief) | 못 먹는 것. 사람에 붙는다 |
| foods | id, name, name_en, tags[], cuisine | 음식 목록. 기본 40개 |
| groups | id, name(1~40), invite_code(6, 유일), created_by | 모임 |
| memberships | group_id, user_id, display_name(1~20), joined_at, (group_id, display_name) 유일 | 모임 소속. 모임 안에서 부르는 이름 |
| sessions | id, group_id, host_user_id, status(open/voting/done), decided_food_id, decided_at | 한 판 |
| session_participants | session_id, user_id, voted(bool), joined_at | 그 판의 참여자 |
| candidates | session_id, food_id, proposed_by, pitch(≤60), vetoed(bool), (session_id, food_id) 유일 | 후보. 원인은 저장하지 않는다 |
| votes | session_id, user_id, food_id, 같은 사람·음식 유일 | 표. 본인만 읽는다 |
| meals | id, group_id, session_id, food_id, eaten_at | 식사 기록 |
| meal_participants | meal_id, user_id | 같이 먹은 사람 |

집계(뷰): 두 사람이 같이 먹은 횟수, 사람별 음식별 횟수, 모임별 음식별 횟수, 사람별 총 끼니.

권한(RLS):
- 모임 데이터는 그 모임 소속만 읽는다
- votes는 본인 행만 읽는다
- 상태를 바꾸는 일(참여, 후보, 투표, 룰렛, 못 먹는 것 저장, 계정 삭제)은 RPC로만 한다. 테이블에 직접 쓰지 않는다
- profiles는 로그인한 사람이 읽을 수 있고 본인만 쓴다

서버 함수(RPC): create_group, get_group_by_code, join_group, start_session, join_session, add_candidate, set_pitch, remove_candidate, open_voting, cast_vote, spin_roulette, session_vote_counts(끝난 판에서만 음식별 표 수), get_my_restrictions, set_my_restrictions, save_my_profile, delete_my_account.

실시간 구독: sessions, session_participants, candidates, votes(본인 것만 오지만 변경 신호로 쓴다). 변경이 오면 그 판을 통째로 다시 읽는다.

## 6. 테스트로 고정할 규칙

- 거부권: 재료 태그 / 식단 태그(짝 없음) / 음식 직접 지정 각각 빠지는지, 상관없는 음식은 남는지

- 익명: 다른 사람 표 조회 0행, 후보 데이터에 원인 사람이 없음
- 온보딩 점수: 네 축 계산과 네 글자
- 레벨: 삼각수 경계
- 아이디 형식

## 8. 환경과 외부 서비스

환경변수 (`.env`, 커밋 금지. `.env.example`에 이름만):
- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_ANON_KEY` (publishable 키. 서비스 키는 앱에 절대 넣지 않는다)
- `EXPO_PUBLIC_WEB_BASE` (초대 링크용 웹 주소)

GitHub Actions 저장소 변수: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `WEB_BASE`. 비밀: `EXPO_TOKEN` (Expo 조직의 robot 토큰)

계정과 소유:
- Supabase와 Expo는 개인 계정이 아니라 각각 조직(Organization) 안에 프로젝트를 둔다. 세팅은 Aninnom, eoieiie도 두 조직의 Owner다
- GitHub 시크릿과 변수는 저장소 관리자(eoieiie)가 넣는다. 토큰은 채팅으로 주고받지 않고, 만든 사람이 바로 저장소에 넣는다
- Apple Developer 계정은 eoieiie 것을 3단계에서 Expo 조직에 연결한다

Supabase 준비:
1. Supabase 조직 안에 프로젝트 생성 (서울 리전)
2. `supabase/migrations/`를 번호 순서대로 SQL Editor에서 실행, 그다음 `supabase/seed/`
3. Authentication에서 Anonymous sign-ins 켜기 (안 켜면 첫 화면에서 멈춘다)
4. Realtime 켜져 있는지 확인

실행:

```bash
npm install
cp .env.example .env
npx expo start
```

CI:
- PR마다: 타입 검사, 린트, 테스트, 웹 번들 빌드
- PR마다: 웹 미리보기 배포. PR 댓글에 미리보기 주소가 달리고, 커밋을 올리면 그 댓글이 새 주소로 바뀐다. 초대 링크는 main 주소를 쓴다. main 주소는 바뀌지 않는다 (이슈 #11, #23)
- 매일 09:00(KST): Supabase에 요청 한 번 (무료 요금제가 1주일 안 쓰면 멈춤)

배포: 1단계부터 웹은 EAS Hosting으로 배포한다. iOS 빌드, TestFlight, App Store 제출(3단계)은 Expo 조직의 EAS 프로젝트에 eoieiie의 Apple Developer 계정을 연결해서 한다.

## 9. 작업 방식

- 기능 하나 = 이슈 하나. 이슈에 이 문서의 해당 절 번호와 완료 기준을 적는다
- 브랜치 `feat/이슈번호-영문요약`, 커밋 `종류: 내용`(한국어), main 직접 push 금지, PR 리뷰 1명
- AI에게 일을 시킬 때: 이 문서 전체 + 관련 파일 전문 + 해당 절의 완료 기준을 준다. 완료 기준이 없으면 코드를 쓰지 않는다
- AI가 낸 결과의 채택·수정·폐기는 `PROMPTS.md`에 남긴다

시작 전에 필요한 것: Expo 조직을 만들고 eoieiie를 Owner로 초대한다. `eas init`은 A 브랜치에서 직접 한다. `EXPO_TOKEN`과 GitHub 변수는 eoieiie가 넣는다 (8절).
- [ ] 각자 노트북에서 `npm install`, `cp .env.example .env`, `npx expo start --web` 세 줄로 같은 홈 화면이 뜬다. Node 버전은 `.nvmrc`로 고정한다
- [ ] `main`에 합쳐지면 웹 주소가 갱신되고, 누구나 설치 없이 그 링크로 앱을 연다
- [ ] 처음 열면 가입 화면 없이 익명 계정이 생긴다. 확인 중에는 로딩, 실패하면 "연결할 수 없어요"와 다시 시도 버튼 (4-1)
- [ ] 폴더가 화면 / 데이터 접근 / 상수로 나뉘고, 화면 폴더에서 `supabase`를 검색하면 0줄이다
- [ ] PR을 열면 타입 검사, 린트, 테스트, 웹 빌드가 자동으로 돈다 (8절 CI)
- [ ] `.env`는 커밋되지 않고 `.env.example`에 이름만 있다
- 확인하는 법: 네 명이 각자 실행한 화면, 휴대폰 브라우저로 웹 주소 열기, 시크릿 창으로 열기, 인터넷을 끊고 열기
- 넘기는 것: PR 본문에 웹 주소, 실행 세 줄, 폴더마다 무엇을 두는지

### B. 데이터베이스와 서버 규칙 (Aninnom)
만드는 것: 데이터를 저장하는 표, 누가 무엇을 볼 수 있는지 정하는 권한, 거부권·투표·룰렛 규칙을 실행하는 서버 함수.
시작 전에 필요한 것: Supabase 조직과 프로젝트(서울 리전)를 만들고 익명 로그인을 켠 뒤, eoieiie를 Owner로 초대한다. 주소와 공개 키는 팀원에게 DM으로 전달하고 저장소에 올리지 않는다.
- [ ] 5절의 표와 권한이 `supabase/migrations/`에 번호 순서대로 있고, 새 프로젝트에 순서대로 실행하면 오류 없이 끝난다. 기본 음식 40개가 들어간다
- [ ] 상태를 바꾸는 일(참여, 후보, 투표, 룰렛, 못 먹는 것 저장)은 5절 서버 함수로만 된다. 테이블에 직접 쓰면 거절된다
- [ ] 다른 사람의 표를 조회하면 0행이 나온다
- [ ] 후보 데이터에 못 먹는 원인이 된 사람이 남지 않는다
- [ ] 6절 서버 규칙 테스트가 통과한다: 거부권 3종(재료, 식단, 음식 지정)과 상관없는 음식은 남는지, 3번째 표 거절과 취소 후 다시 찍기, 룰렛 대상(1표 이상 / 아무도 안 찍으면 전체 / 빠진 후보 제외), 표 수 비례 확률
- 확인하는 법: 계정 두 개로 투표한 뒤 서로의 표 조회, 앱 키로 테이블에 직접 쓰기 시도, 테스트 실행 결과
- 넘기는 것: PR 본문에 서버 함수마다 이름, 받는 값, 돌려주는 값을 표로 (C, D, E, F가 이걸 보고 부른다)

### C. 홈, 모임 만들기, 모임 화면 (GONI1130)
만드는 것: 앱 첫 화면(내 모임 목록), 모임 만들기, 모임 화면(초대 링크, 멤버, 최근 식사, 판 시작 버튼).
시작 전에 필요한 것: A의 뼈대. B가 끝나기 전에는 가짜 데이터로 화면을 먼저 만든다.
- [ ] 모임 이름(1~40자)과 내 이름(1~20자)을 적으면 모임과 6자 초대 코드가 생기고 모임 화면으로 간다. 이름이 비면 버튼이 꺼지고, 서버 오류는 창 안에 한국어 문구로 보여주고 창을 닫지 않는다 (4-2)
- [ ] 홈에 내 모임이 최근에 들어간 순으로 보인다. 없으면 "아직 모임이 없어요"와 만들기 버튼, 오류면 문구와 다시 시도 버튼 (4-3)
- [ ] 초대 카드를 누르면 `{웹 주소}/g/{초대코드}`가 복사되고 "복사했어요"가 2.5초 보인다. 앱에서 복사해도 웹 주소다. 복사가 안 되면 링크 글자를 보여준다 (4-4)
- [ ] 모임 화면에 초대 카드, 멤버 이름 동그라미, 최근 식사 5개가 있다. 진행 중인 판이 있으면 "진행 중인 판으로", 없으면 "오늘 뭐 먹지". 소속이 아니면 "이 모임 멤버가 아니에요"와 홈으로 버튼 (4-6)
- 확인하는 법: 모임 두 개를 만들어 순서 보기, 빈 이름으로 눌러 보기, 다른 계정으로 모임 주소를 직접 열기
- 넘기는 것: "오늘 뭐 먹지" 버튼 자리(E가 연결), 초대 링크 주소 형식(D가 받는다)

### D. 초대 링크 참여, 못 먹는 것 (Ruty041)
만드는 것: 링크를 받은 사람이 웹에서 이름만 적고 들어오는 화면(`/g/{초대코드}`), 못 먹는 것 등록 화면.
시작 전에 필요한 것: C의 초대 코드, B의 참여·못 먹는 것 서버 함수.
- [ ] 다른 브라우저(시크릿 창)에서 초대 링크를 열면 모임 이름이 보이고, 이름(1~20자)만 적으면 설치·가입 없이 들어간다. 진행 중인 판이 있으면 그 판으로, 없으면 모임 화면으로 (4-5)
- [ ] 이미 소속이면 묻지 않고 넘어간다. 프로필에 이름이 있으면 "OO(으)로 들어갈게요" 버튼만 보인다 (4-5)
- [ ] 없는 코드는 "모임을 찾을 수 없어요", 같은 이름은 "이미 있는 이름이에요", 이름이 비면 버튼이 꺼지고, 네트워크 오류는 다시 시도 버튼 (4-5)
- [ ] 재료 8개·식단 3개 태그, 음식 검색(최대 6개), 이유(알레르기 / 안 먹어요 / 신념)를 골라 저장하면 내가 속한 모든 모임에 적용된다 (4-7)
- [ ] 저장하면 진행 중인 판의 후보가 다시 판정된다 (E와 함께 확인) (4-7)
- [ ] 저장에 실패하면 문구를 보여주고 고른 것을 그대로 둔다. 아무것도 안 고르고 저장하면 전부 해제된다 (4-7)
- 확인하는 법: 시크릿 창으로 링크 열기, 없는 코드 주소 열기, 같은 이름으로 두 번 들어가기, 해산물을 막은 뒤 후보에서 빠지는지 보기
- 넘기는 것: 세션 화면 위쪽에 둘 "못 먹는 것" 버튼(E가 자리를 만든다)

### E. 세션, 후보, 투표 (Aninnom)
만드는 것: 한 판의 화면. 후보를 올리고 투표하기까지. 모든 기기가 실시간으로 같은 상태를 본다.
시작 전에 필요한 것: C의 모임 화면, B의 세션·후보·투표 서버 함수.
- [ ] 모임에서 시작하면 진행 중인 판이 있으면 그 판, 없으면 새 판이 열리고 연 사람이 방장이다. 화면에 들어오면 자동으로 참여자가 된다. 끝난 판에 들어오면 결과를 보여준다 (4-8)
- [ ] 음식을 검색해 후보로 올린다. 이미 올라간 음식은 검색 목록에서 빠진다. 내가 올린 후보에는 어필(60자)과 빼기가 있다 (4-9)
- [ ] 못 먹는 사람이 있는 후보는 줄이 그어지고 "못 먹는 사람이 있어서 빠졌어요"가 보인다. 누가 원인인지는 어디에도 안 보인다. 투표가 시작된 뒤 올리면 "이미 투표가 시작됐어요" (4-9)
- [ ] 방장이 투표를 시작하면 모든 기기가 투표 화면으로 바뀐다. 빠지지 않은 후보가 0개면 버튼이 꺼지고 "후보를 하나 이상 올려주세요". 방장이 아니면 "방장이 투표를 열면 시작돼요" (4-10)
- [ ] 1인 최대 2표, 3개째는 "최대 2개까지 고를 수 있어요", 빠진 후보는 누를 수 없다. "N/M명 투표했어요"가 갱신되고, 투표 중에는 음식별 표 수가 안 보인다 (4-11)
- [ ] 한 기기에서 바꾼 것(참여, 후보, 투표 진행)이 다른 기기에 새로고침 없이 3초 안에 보인다
- 확인하는 법: 브라우저 3개로 같은 판에 들어가 동시에 누르기
- 넘기는 것: 투표 화면 아래 "돌리기" 버튼 자리(F가 연결)

### F. 룰렛, 식사 기록, 3대 확인 (eoieiie)
만드는 것: 방장이 돌리면 모든 기기에서 같은 결과로 멈추는 원판, 자동 식사 기록, 그리고 1단계 전체 확인.
시작 전에 필요한 것: E의 투표 화면, B의 룰렛 서버 함수.
- [ ] 방장이 돌리면 서버가 표 수에 비례해 하나를 고르고 모든 기기가 같은 결과에 멈춘다. 아무도 안 찍었으면 빠지지 않은 후보 중 균등하게 (4-12)
- [ ] 원판 조각 크기는 표 수에 비례한다. 음식별 표 수는 결과가 나온 뒤에만 받는다 (4-12)
- [ ] 3.6초 동안 5바퀴 돌고 감속, 조각을 지날 때와 멈출 때 진동, 7글자가 넘는 이름은 자른다. 화면이 뒤로 가 있어도 4초 뒤에는 결과가 보인다 (4-12)
- [ ] 결과가 나오면 식사 기록이 자동으로 생기고 모임 화면의 최근 식사에 보인다 (4-13)
- [ ] 서로 다른 기기 3대로 1절 1단계 완료 기준 10개를 처음부터 끝까지 확인하고, 결과를 PR 본문에 체크리스트로 남긴다. 이게 MVP 완료다
- 확인하는 법: 3대로 한 판 끝내기, 표를 3:1로 몰아 여러 번 돌려 비율 보기, 한 기기를 백그라운드로 보낸 채 돌리기
