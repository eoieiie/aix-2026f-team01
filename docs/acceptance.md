2026-11-25 씀 (eoieiie). 결과보고서 2.4(사용자 스토리와 완료 조건), 6.2(완료 조건 달성 여부)의 재료다. 4주차 활동지(`docs/week-04.md`)의 AC 표 형식(EARS 문장, 정상/실패 경로, 판정 방법)을 따른다.

## 4주차 AC와 바뀐 이유

4주차에 쓴 AC-1~3은 "킥보드 통합 플랫폼" 주제의 것이다. 9/30에 주제를 밥비티아이로 바꿨다. 킥보드는 사업자 위치·결제 API 제휴 없이는 시연할 수 없어서다(`docs/decisions.md` 2026-09-30). 아래는 밥비티아이 핵심 시나리오(모임 → 판 → 후보 → 투표 → 룰렛 → 결과) 기준으로 새로 쓴 것이다.

## 판정 기준

- "통과": 판정 방법에 적은 자동 테스트가 실제로 돌아 통과했다. jest는 2026-11-25 오후 main `04d83d8` 기준 로컬 실행(25개 파일, 215개 통과), pgTAP(`supabase/tests/`)은 main `04d83d8`의 GitHub Actions `db` 검사 통과로 확인했다
- "부분": 서버 규칙은 자동 테스트로 통과했지만, 화면이나 바깥 서비스(실시간 도착, Gemini 실제 호출)는 사람이 한 번 확인한 기록만 있다
- "미달성": 아직 안 된다
